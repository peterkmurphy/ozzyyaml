# ozzyyaml 0.2.0 pre-release — Design Spec

**Date:** 2026-11-26  
**Status:** Approved for implementation planning  
**Source workorder:** external audit / pre-release workorder (rejection harness,
PyO3 0.30, fuzzing)  
**Parent:** [2026-11-25-ozzyyaml-grammar-complete-design.md](./2026-11-25-ozzyyaml-grammar-complete-design.md),
[2026-11-25-ozzyyaml-python-compose-suite-design.md](./2026-11-25-ozzyyaml-python-compose-suite-design.md)

## Intent

Cut `v0.2.0` only when ozzyyaml is honest and measurable on **both**
yaml-test-suite halves, ships modern Python wheels (including 3.14 and macOS
Intel via cross-compile), records free-threading smoke status, and runs
bounded fuzzing in CI.

Baseline verified on current `main` at design time:

- Valid `test.event`: **255 / 255** exact match
- Invalid (`error` marker): **57 / 78** correctly reject; **21** false accepts

False-accept IDs (empirical):  
`3HFZ 4EJS 5TRB 5U3A 9C9N 9JBA 9KBC CVW2 CXX2 G5U8 G9HC H7J7 N782 QB6E RXY3
S98Z SU5Z SY6V U99R X4QW YJV2`

## Decisions locked in brainstorming

| Topic | Choice |
| --- | --- |
| Wheel ABI | Per-interpreter (`3.10`–`3.14`), not `abi3-py310` |
| Free-threading | CI smoke on 3.14t + honest docs (not a full support claim) |
| Contested error cases | Reject unless YAML 1.2.2 clearly allows; document only true ambiguities |
| Sequencing | Workorder as written: Item 1 → then Items 2 ∥ 3 → bump → tag |

## Goals

1. **78/78** invalid suite cases rejected (hard gate; named deviations only if unavoidable).
2. PyO3 **0.30**; wheels for CPython **3.10–3.14** on Linux/Windows/macOS (arm64 + x86_64 macOS).
3. Real **cargo-fuzz** targets + CI (push/PR bounded + nightly longer).
4. Version **0.2.0**; docs claim **255/255 valid + 78/78 invalid** (plus free-threading and fuzz status lines).

## Non-goals (this tag)

- `abi3-py310`, musllinux/Alpine wheels, i686
- Full free-threaded “supported” product claim
- Emit presentation fidelity, Serde, round-trip/shape allowlist → 255
- Cyclic-root `Rc::try_unwrap` shell cleanup (unless a fuzz finding forces it)
- Python event / `test.event` API

## Item 1 — Error-case rejection harness

**Harness:** `crates/ozzyyaml-parser/tests/yaml_test_suite_errors.rs`

- Enumerate dirs with `in.yaml` **and** `error` marker.
- Assert `parse_str(in.yaml)` returns `Err`.
- No allowlist. Collect-all failures: `{id}: falsely accepted` or `{id}: {err}` if a case panics.
- Keep valid gate `all_valid_event_suite_cases_match` green after every fix.

**Fix families (TDD by family / representative ID):**

| Family | Representatives | Required behavior |
| --- | --- | --- |
| Content after document markers | 3HFZ, 5TRB, RXY3, N782, SU5Z, S98Z, SY6V, U99R | Garbage adjacent to `---` / `...` is an error, not a silent second document |
| Tabs in indentation | 4EJS | Tab in block indentation is a scan error (§8.2.1); tabs as content remain legal |
| Trailing junk after flow close | 9JBA, CVW2 | Non-whitespace after flow close (other than ` #` comment) is an error |
| Anchor/tag placement | G9HC, H7J7, 5U3A | Anchor/tag and decorated node must be positionally valid |
| Multi-line quoted flaws | QB6E | Match suite expectation, not a fixed guess |
| Remainder | 9C9N, 9KBC, CXX2, G5U8, X4QW, YJV2, … | Case-by-case after reading suite notes |

**Ambiguity policy:** Prefer YAML 1.2.2 over “what libyaml does.” If a case is
genuinely contested after reading suite `tags` / notes, document a **named**
deviation in `docs/conformance.md` and exclude only those IDs from the hard
gate (prefer zero exclusions).

**Docs / CI:**

- `docs/conformance.md`: invalid **78/78** (or `N/78` + deviation list) via
  `all_error_suite_cases_reject`.
- README: any “100%” wording must cite **both** halves.
- CI: `cargo test -p ozzyyaml-parser` already runs both gates; add a visible
  summary step/job that prints `255/255 valid + 78/78 invalid` when green.

## Item 2 — PyO3 0.30, Python 3.14, wheel matrix

**Code:** Bump `pyo3` to `0.30` in `crates/ozzyyaml-python/Cargo.toml`. Fix
API churn (`IntoPyObject`, `Bound`, deprecations). Public Python API unchanged.

**Publish matrix (`publish-pypi.yml`):**

- `MATURIN_INTERPRETERS: "3.10 3.11 3.12 3.13 3.14"`
- Extend Windows interpreter matrix the same way
- Delete outdated “PyO3 0.23 / do not use 3.14” comments

**macOS Intel (Item 2a):** On `macos-latest` (Apple Silicon), matrix targets
`aarch64-apple-darwin` and `x86_64-apple-darwin` via maturin-action `target`.
Separate arch wheels (not universal2). x86_64 in-CI smoke via Rosetta is
best-effort; do not block the release solely on that smoke.

**Free-threading:** Add a CI smoke that imports the extension under a
free-threaded 3.14t build where practical. `docs/python.md` states
smoke-validated, not fully supported.

**Metadata:** `python/pyproject.toml` classifiers + `requires-python` cover
3.14; remove README workaround text that implies 3.14 is unusable.

## Item 3 — Fuzzing

**Layout:** `fuzz/` with cargo-fuzz targets:

1. `fuzz_parse_str` — panic/unwind = finding; limit/OOM blow-through = finding;
   `Ok` or `Err` is fine.
2. `fuzz_roundtrip` — if parse+compose+emit path accepts input,
   `from_str → to_string → from_str` must succeed again.

**Seed corpus:** every yaml-test-suite `in.yaml` (valid and error), unit
fixtures for folding / block scalars / explicit keys, plus a small generative
seed mutating `---` / `...` / `|` / `>` / `?` / `&` / `*` / `!` indicators.

**CI:** bounded fuzz duration on push/PR; longer **nightly** job; log corpus
growth. **Findings policy:** panic blocks `v0.2.0`; limit issues triaged to
`Limits` or a code fix with a written outcome before tag.

## Release gate

1. Items 1–3 acceptance green (including fuzz triage notes if any findings).
2. Bump workspace `Cargo.toml` + `python/pyproject.toml` (+ path-dep pins) to
   **0.2.0**.
3. Update README / `conformance.md` / `python.md` claims.
4. Tag `v0.2.0` and confirm Trusted Publishing workflows.

## Success criteria

| Criterion | Check |
| --- | --- |
| Invalid suite | `all_error_suite_cases_reject` green (78/78 or documented named set) |
| Valid suite | Still 255/255 event equality |
| PyO3 / 3.14 | Local or CI wheel build + import smoke on 3.14; publish workflow lists 3.14 |
| macOS x86_64 | Workflow builds `x86_64-apple-darwin` wheels |
| 3.14t | CI smoke present; docs honest |
| Fuzz | `fuzz/` runs locally; nightly (and bounded PR) job exists; findings triaged |
| Version | Tree at 0.2.0 before tag |

## Implementation order

1. Item 1 harness + family fixes + docs/CI summary  
2. Item 2 and Item 3 in parallel once Item 1 is green (or Item 1 far enough that scanner churn has settled)  
3. Version bump + final doc pass + tag
