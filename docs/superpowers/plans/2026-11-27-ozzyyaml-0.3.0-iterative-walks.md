# ozzyyaml 0.3.0 Iterative Tree Walks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate depth-proportional Rust recursion in every `Value` consumer so `max_nesting_depth` is only a DoS/memory guard, then re-raise the default to 10 000 and ship 0.3.0.

**Architecture:** Keep the parser and composer as explicit-stack state machines. Convert emit (`Anchors::count`, `Writer::{flow,block}`), `Value::Drop`, and the three Python converters to work-stack iteration. Extend nesting boundary tests after each crate lands; only then raise `Limits::default().max_nesting_depth`.

**Tech Stack:** Rust workspace (`ozzyyaml`, `ozzyyaml-emit`, `ozzyyaml-python`), existing `nesting_boundary` tests, PyO3 0.30, cargo test / maturin.

## Global Constraints

- Suite gates `all_valid_event_suite_cases_match` (255) and `all_error_suite_cases_reject` (78) green every commit.
- Nesting boundary tests green every commit; never weaken them.
- One PR per crate touched (emit → Value Drop → python), honest commits, no bundling.
- `forbid(unsafe_code)` preserved.
- Do not publish 0.3.0 until Track 3 (isityaml dogfood) has battle-tested the raised default when possible; structural PRs may land earlier.
- Composer (`crates/ozzyyaml/src/compose.rs`) is **already iterative** (`frames: Vec<Frame>`) — verify with a small-stack deep-compose test; do not rewrite unless a recursive path remains.
