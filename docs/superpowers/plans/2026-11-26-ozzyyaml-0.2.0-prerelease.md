# ozzyyaml 0.2.0 pre-release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `v0.2.0` with 78/78 invalid suite rejection, PyO3 0.30 + CPython 3.10–3.14 wheels (incl. macOS Intel cross-build + 3.14t smoke), and CI fuzzing.

**Architecture:** Add a hard error-suite gate mirroring the valid event gate; fix scanner/parser false accepts by defect family (TDD). Independently bump PyO3/publish matrix and add cargo-fuzz targets with bounded + nightly CI. Tag only after all three acceptance sections and the version bump.

**Tech Stack:** Rust 2021 (`ozzyyaml-parser` / `ozzyyaml` / `ozzyyaml-emit` / `ozzyyaml-python`), PyO3 0.30, Maturin, cargo-fuzz, GitHub Actions, vendor `yaml-test-suite`.

## Global Constraints

- Valid suite must stay **255/255** event equality after every scanner change.
- Invalid suite target **78/78** reject; named deviations only if YAML 1.2.2 is genuinely ambiguous (document in `conformance.md`).
- Wheels: **per-interpreter** `3.10`–`3.14` (not `abi3-py310`).
- Free-threading: **CI smoke** + honest docs, not a full support claim.
- Do **not** tag `v0.2.0` until Items 1–3 acceptance are green and version is `0.2.0`.
- Spec: `docs/superpowers/specs/2026-11-26-ozzyyaml-0.2.0-prerelease-design.md`.

### Task 1: Error-suite hard gate (expect ~21 failures)

**Files:**
- Create: `crates/ozzyyaml-parser/tests/yaml_test_suite_errors.rs`

**Interfaces:**
- Consumes: `ozzyyaml_parser::parse_str`, vendor suite layout
- Produces: `all_error_suite_cases_reject` test

- [ ] **Step 1: Write the harness**

```rust
//! Every yaml-test-suite case with an `error` marker must fail to parse.

use ozzyyaml_parser::parse_str;
use std::path::{Path, PathBuf};

fn suite_root() -> PathBuf {
    PathBuf::from(env!("CARGO_MANIFEST_DIR")).join("../../vendor/yaml-test-suite")
}

fn error_suite_ids(root: &Path) -> Vec<String> {
    let mut ids: Vec<_> = std::fs::read_dir(root)
        .expect("suite root")
        .filter_map(Result::ok)
        .filter(|e| e.path().is_dir())
        .map(|e| e.file_name().to_string_lossy().into_owned())
        .filter(|id| {
            let d = root.join(id);
            d.join("in.yaml").is_file() && d.join("error").exists()
        })
        .collect();
    ids.sort();
    ids
}

#[test]
fn all_error_suite_cases_reject() {
    let root = suite_root();
    assert!(
        root.join("2AUY").is_dir() || root.join("229Q").is_dir(),
        "yaml-test-suite submodule missing; run `git submodule update --init`"
    );

    let ids = error_suite_ids(&root);
    assert!(!ids.is_empty(), "no error suite cases found");

    let mut failures = Vec::new();
    for id in &ids {
        let input = std::fs::read_to_string(root.join(id).join("in.yaml"))
            .unwrap_or_else(|e| panic!("{id}: cannot read in.yaml: {e}"));
        match parse_str(&input) {
            Ok(_) => failures.push(format!("{id}: falsely accepted")),
            Err(_) => {}
        }
    }

    assert!(
        failures.is_empty(),
        "error-suite false accepts ({}):\n{}",
        failures.len(),
        failures.join("\n")
    );
}
```

- [ ] **Step 2: Run — expect fail listing ~21 IDs**

```bash
cargo test -p ozzyyaml-parser --test yaml_test_suite_errors -- --nocapture
```

Expected: FAIL with `falsely accepted` lines including at least  
`3HFZ 4EJS 5TRB 5U3A 9C9N 9JBA 9KBC CVW2 CXX2 G5U8 G9HC H7J7 N782 QB6E RXY3 S98Z SU5Z SY6V U99R X4QW YJV2`.

- [ ] **Step 3: Commit the failing harness** (red is intentional; next tasks turn it green)

```bash

git commit -m "$(cat <<'EOF'

EOF
)"
```
